# ScamDrill

**ScamDrill** is a practice simulator: an AI plays a fictional scam caller, you play
through the call, and afterwards you see which pressure tactics worked on you — and
what to say instead.

It is a **practice tool, not a study**. It does not claim to reduce fraud or improve
outcomes. The quiz score change shown in the demo is an illustration, not a result.
Everything in the app is fictional: the bank, the caller, the courier, the phone
numbers. Never type real personal data.

## How it works

1. **Home** — pick a scenario and language (English default). A fictional-only
   disclaimer is shown.
2. **Pre-quiz** — 5 multiple-choice questions.
3. **Call** — chat-style conversation with the AI scam caller. A "Hang up" button is
   always visible. At three points a **Decision Card** appears with 3 choices.
4. **Debrief** — a tactic timeline showing "worked on you / you resisted" per tactic,
   a weak-spot card, "what to say instead" for each unsafe moment, and 3 plain-language
   rules.
5. **Post-quiz** — a different 5 questions of equal difficulty; score change shown.
6. **Share** — copy a link to your weak-spot card, or a "send this practice to a family
   member" link that pre-selects scenario and language. No accounts, no database.

### The differentiator: tactic tags as ground truth

The scammer is generated by us, so we know which pressure tactic each line uses.
The debrief uses those tags as ground truth — there is no detection or guessing step.
Tactic IDs (fixed): `authority`, `urgency`, `fear`, `isolation`, `trust_building`,
`verification_blocking`, `credential_request`, `remote_access`, `payment_request`.

## How Nemotron is used

Two model roles, both configured by environment variable (never hardcoded):

| Role | Model (Nemotron class) | Job |
|------|------------------------|-----|
| `MODEL_FAST` | `nvidia/Nemotron-3-Nano-30B-A3B` (nano) | Phrases each caller turn (1–3 short sentences, in-character). |
| `MODEL_REASON` | `nvidia/nemotron-3-super-120b-a12b` (super) | Writes the debrief (summary, moments, rules). |

The **engine decides** (state machine: stage advance, decisions, hang up); the **model
only phrases** the caller's line. Decision outcomes are scored from the scenario JSON,
never from the model. Generation settings: temperature ~0.7 / max_tokens ~150 for
caller turns; temperature ~0.3 / max_tokens ~600 for the debrief. Timeouts (~20 s)
with one backoff retry on rate-limit/transient errors.

## How Nebius Token Factory is used

- Both models are called through **Nebius Token Factory's OpenAI-compatible API**
  (`https://api.tokenfactory.nebius.com/v1`, `Authorization: Bearer <token>`).
- A runtime call to the Token Factory inference API powers every caller turn and the
  debrief — this counts toward the hackathon requirement.
- JSON output mode (`response_format: {"type": "json_object"}`) is used for structured
  responses, with a parse-validate-fallback path so the app never shows a broken turn.

No other Nebius tools are currently used (Nebius Serverless Endpoints is optional and
not used).

## Scenarios

Two fictional scenarios in `backend/scenarios/`, validated with pydantic on startup:

- **bank_call** — "The bank security call" (Daniel Reyes, Northgate Bank — fictional)
- **parcel_fee** — "The parcel delivery fee" (Sarah Chen, SwiftParcel Courier — fictional)

Each has 5 stages and 3 decision cards with safe/unsafe outcomes and feedback.

## Safety & privacy

- **Fictional only.** Banner on Home and Call screens. No real brands, numbers, or URLs.
- **Input masking** (server-side, before any model call): digit runs of 6+, email
  addresses, and phone-like strings replaced with `[hidden]`.
- **Output filter** on every caller line: rejects URLs, emails, phone-like strings, and
  real bank/courier names; falls back to stage `fallback_lines`.
- The caller never gives operational fraud instructions and deflects fraud-how-to
  questions.
- **No user messages are logged.** Only counters and error types are logged.
- Every call ends with a debrief — no session ends on the scammer "winning" without
  coaching.
## Run locally

```bash
# 1. Clone the repo
git clone <repo-url>
cd ScamDrill

# 2. Copy env template and add your keys (never commit .env)
cp .env.example .env
# edit .env: set LLM_PROVIDER, LLM_BASE_URL, LLM_API_KEY, MODEL_FAST, MODEL_REASON

# 3. Backend
pip install -r requirements.txt
python3 -m uvicorn backend.app.main:app --reload

# 4. Frontend (separate terminal)
cd frontend
npm install
npm run dev   # proxies /api to localhost:8000
```

## Environment variables

See `.env.example`. Key variables:

- `LLM_PROVIDER` — `openrouter` (testing) or `nebius` (final/deploy)
- `OPENROUTER_API_KEY` / `OPENROUTER_BASE_URL` — for testing
- `NEBIUS_API_KEY` / `NEBIUS_BASE_URL` — for Nebius Token Factory
- `MODEL_FAST` — e.g. `nvidia/Nemotron-3-Nano-30B-A3B`
- `MODEL_REASON` — e.g. `nvidia/nemotron-3-super-120b-a12b`
- `DAILY_CALL_CAP` — global daily call cap for cost protection
- `DEMO_MODE=replay` — serves `demo/recorded_run.json` instead of live API

## Deploy

Single Dockerfile builds the frontend and runs the FastAPI app. Deploy to any free host
with a public URL (Render, Fly.io, Railway, etc.). The app is stateless (no database),
so restarts are safe. Free tiers sleep — warm the app before use.

Per-IP rate limiting and `DAILY_CALL_CAP` protect against cost overruns; when the cap
is reached, a friendly "demo is at capacity" message is shown.

`DEMO_MODE=replay` replays `demo/recorded_run.json` so the demo video can be recorded
reliably even if the API is slow. Replay mode is **not** used in the judged deployment
unless the live API is down.

## Testing

- **Unit tests** (`backend/tests/`): schema validation, engine state transitions,
  decision scoring, input masking, output filter, JSON parsing/fallback.
- **Regression harness** (`eval/run_regression.py`): 3 personas × 2 scenarios × 3
  repeats against the live model, with assertions on every caller turn.
- Transcripts saved in `eval/transcripts/`. Real results (including failures) are
  reported here once live-key testing is complete.

## Limitations and honest scope

- Practice tool only — not a replacement for official advice, not a study.
- No real statistics are claimed anywhere (spec §7).
- Hindi is not shipped (deferred; see DECISIONS.md).
- Share/practice links work client-side; no backend storage.
- The demo depends on the LLM provider being available; `DEMO_MODE=replay` is the
  fallback.
